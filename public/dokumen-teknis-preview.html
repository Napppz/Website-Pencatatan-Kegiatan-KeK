DOKUMEN TEKNIS PENGEMBANGAN WEBSITE Log_Book_Rapat KEK

1. Pendahuluan

1.1. Latar Belakang

Dalam rangka mendukung tata kelola pemerintahan yang efektif, transparan, dan akuntabel di lingkungan Sekretariat Jenderal Dewan Nasional Kawasan Ekonomi Khusus (Setjen DN KEK), pelaksanaan koordinasi dan perumusan kebijakan strategis memerlukan sistem pendokumentasian yang andal. Setiap agenda rapat dinas, perumusan regulasi kawasan, percepatan investasi hilirisasi, serta fasilitasi kerja sama ekonomi menghasilkan keputusan-keputusan krusial yang harus dicatat, ditindaklanjuti, dan dipertanggungjawabkan secara tepat waktu.

Pengelolaan log rapat dinas, penyusunan risalah notulensi, dan pemantauan butir tindak lanjut (action items) yang sebelumnya dilakukan secara manual menimbulkan berbagai kendala administratif seperti terjadinya duplikasi penomoran agenda, keterlambatan distribusi arahan pimpinan, sulitnya pelacakan progres pekerjaan secara real-time, serta hilangnya jejak audit riwayat revisi.

Oleh karena itu, diperlukan pengembangan Website Sistem Informasi Log & Notula Rapat (Log_Book_Rapat KEK) yang mampu mengintegrasikan seluruh tahapan mulai dari penjadwalan rapat, pencatatan presensi, penyusunan notulensi terstruktur, pengesahan risalah, hingga pemantauan status penyelesaian tindak lanjut dalam satu ekosistem terpadu.

1.2. Tujuan Dokumen

Dokumen teknis ini disusun dengan tujuan untuk:

  1. Menjadi acuan baku dalam pengembangan dan pengelolaan website Log_Book_Rapat KEK.
  2. Memberikan gambaran menyeluruh terkait arsitektur sistem, alur proses bisnis, dan desain antarmuka.
  3. Mendokumentasikan struktur sistem, database, serta relasi data secara lengkap.
  4. Memudahkan proses pemeliharaan (maintenance) dan pengembangan sistem lanjutan.
  5. Menjadi dokumen referensi resmi bagi tim pengembang, pimpinan instansi, dan laporan akademik.

1.3. Ruang Lingkup Sistem

Ruang lingkup pengembangan website Log_Book_Rapat KEK mencakup seluruh proses layanan rapat dinas, antara lain:

  • Pengelolaan dan penjadwalan rapat dinas (judul, tanggal, waktu, lokasi, kategori, berkas lampiran).
  • Otomasi penomoran urut rapat berbasis kode biro/tim pemrakarsa (misal: INV-015).
  • Pencatatan daftar hadir dan konfirmasi presensi peserta rapat.
  • Penyusunan risalah notulensi rapat terstruktur (dinamika sidang, arahan pimpinan, kesimpulan).
  • Pengesahan risalah dan perumusan butir tindak lanjut (action items).
  • Monitoring dan tracking status penyelesaian pekerjaan staf PIC secara berkala.
  • Manajemen pengguna berbasis peran (Staff, Admin Biro, Super Admin).
  • Penyajian dashboard eksekutif dan ekspor laporan risalah resmi.

1.4. Definisi Istilah

Berikut beberapa istilah teknis dan administratif yang digunakan dalam dokumen ini:

  • Log_Book_Rapat KEK: Sistem Informasi Log & Notula Rapat berbasis web terintegrasi di lingkungan Setjen Dewan Nasional KEK.
  • Biro Pemrakarsa: Unit kerja eselon II yang menyelenggarakan agenda rapat dinas.
  • Tim Kerja KEK: Sub-unit kerja operasional (Tim Investasi, Tim Kerja Sama, Tim Komunikasi Publik).
  • Notulis: Staf yang bertugas mencatat dinamika rapat dan menyusun draf risalah notulensi.
  • Tindak Lanjut (Action Items): Butir penugasan kerja hasil kesepakatan rapat yang dibebankan kepada staf PIC.
  • PIC (Person-in-Charge): Staf aparatur penanggung jawab teknis penyelesaian butir tindak lanjut.
  • Nomor Rapat: Kode unik registrasi agenda rapat dinas (contoh: INV-015, KS-008).
  • Frontend: Antarmuka pengguna (tampilan web reaktif berbasis Next.js).
  • Backend: Lapisan logika bisnis, Server Actions, dan Prisma ORM pengelola basis data.

2. Gambaran Umum Sistem

2.1. Deskripsi Sistem

Website Log_Book_Rapat KEK merupakan sistem informasi berbasis web yang dikembangkan untuk mendukung ketertiban administrasi dan akuntabilitas tindak lanjut keputusan rapat dinas secara digital. Sistem ini memungkinkan pimpinan, admin biro, notulis, dan staf pelaksana bekerja sama dalam satu platform tanpa ketergantungan dokumen fisik manual.

Sistem dirancang terintegrasi antara modul penjadwalan, penulisan risalah, pelacakan penugasan, dan evaluasi capaian kinerja tim. Seluruh proses terdokumentasi dalam basis data PostgreSQL ternormalisasi (3NF) guna menjamin keutuhan dan keamanan data instansi.

2.2. Aktor / Pengguna Sistem

Sistem melibatkan 3 kelompok pengguna dengan kewenangan berbeda:

  1. Staf Pelaksana (Staff / PIC):

    Menerima undangan rapat, melakukan konfirmasi presensi, meninjau butir tindak lanjut yang dibebankan, dan memperbarui status progres pengerjaan beserta unggahan berkas bukti.

  2. Admin Biro / Notulis Rapat (Admin):

    Menjadwalkan rapat baru, mengelola nomor registrasi otomatis, mencatat notulensi rapat, merumuskan butir tindak lanjut dan PIC, serta mengajukan pengesahan risalah kepada pimpinan.

  3. Super Admin / Pimpinan:

    Memiliki hak akses penuh, memantau Dashboard Monitoring Eksekutif, mengesahkan risalah notulensi, melakukan evaluasi tindak lanjut, dan mengelola data master (unit kerja & akun pengguna).

2.4. Fitur Utama Sistem

Adapun fitur utama dalam website Log_Book_Rapat KEK meliputi:

  1. Formulir Registrasi & Penjadwalan Rapat: Pendaftaran agenda dinas dengan opsi pimpinan, notulis, dan lampiran.
  2. Otomasi Penomoran Agenda Dinas: Generator penomoran surat rapat urut per tim kerja KEK (INV, KS, KOM).
  3. Editor Risalah Notulensi Terpadu: Pencatatan dinamis poin bahasan dan butir kesimpulan sidang.
  4. Matriks Pemantauan Tindak Lanjut (Action Items Tracker): Delegasi tugas dengan tenggat waktu dan skala prioritas.
  5. Dashboard Monitoring Eksekutif: Ringkasan metrik statistik KPI tim kerja dan filter periode waktu reaktif.
  6. Modul Rekap Presensi Peserta: Manajemen daftar kehadiran dan konfirmasi kehadiran.
  7. Jejak Audit & Riwayat Log: Audit trail perubahan notulensi dan catatan pembaruan progres staf.
  8. Pengelolaan Lampiran Berkas Dinas: Upload materi paparan dan dokumen bukti penyelesaian tugas.
  9. Sistem Notifikasi Pengguna: Notifikasi real-time undangan rapat baru dan penugasan pekerjaan.
  10. Ekspor & Cetak Risalah Resmi: Pencetakan naskah notulensi terformat resmi dan dokumen nota dinas.

2.5. Batasan Sistem

Dalam pengembangannya, sistem website Log_Book_Rapat KEK memiliki beberapa batasan, antara lain:

  1. Sistem dapat diakses melalui jaringan internet dan intranet resmi pemerintah menggunakan protokol HTTPS.
  2. Validasi keaslian data akun bersandar pada basis data pengguna yang terdaftar pada sistem Setjen KEK.
  3. Integrasi dengan sistem eksternal diatur secara terbatas sesuai kebutuhan pertukaran data resmi.
  4. Pengelolaan hak akses sepenuhnya ditentukan berdasarkan peran (Super Admin, Admin, Staff).
  5. Dokumen notulensi yang telah disahkan (status: APPROVED / FINAL) terkunci untuk menjaga orisinalitas naskah hukum.

3. Arsitektur Sistem

3.1. Gambaran Arsitektur Sistem

Website Log_Book_Rapat KEK dibangun menggunakan arsitektur monolitik modern berbasis Next.js 15 Fullstack Framework dengan React Server Components (RSC). Seluruh proses, mulai dari antarmuka pengguna, navigasi halaman, validasi formulir, logika bisnis perizinan, hingga eksekusi kueri basis data dijalankan dalam satu kesatuan aplikasi terintegrasi.

Interaksi pengguna dilakukan melalui browser menggunakan protokol HTTPS, yang kemudian diproses langsung oleh Next.js Server Engine. Sistem mengelola permintaan melalui Server Actions, memproses logika bisnis dengan Prisma ORM, mengakses database PostgreSQL (Neon DB), dan mengembalikan hasil dalam bentuk tampilan reaktif.

DIAGRAM TIGA LAPISAN ARSITEKTUR SISTEM

Application Layer

3.2. Pola Arsitektur Server Components & Actions

Sistem ini menerapkan pola arsitektur Next.js modern yang membagi komponen utama ke dalam:

  • Server Components: Mengambil data langsung di server secara efisien dan aman.
  • Client Components: Menangani interaksi formulir dinamis dan filter reaktif.
  • Server Actions: Mengeksekusi mutasi simpan, perbarui, dan hapus ke basis data.

3.3. Alur Kerja Sistem

Alur kerja sistem secara umum adalah sebagai berikut:

  1. Pengguna mengakses website melalui browser web.
  2. Pengguna melakukan aksi (misalnya menjadwalkan rapat dinas baru).
  3. Request dikirim ke server dan diterima oleh Next.js Server Actions.
  4. Middleware memverifikasi autentikasi sesi dan hak akses peran pengguna.
  5. Server Actions memanggil model Prisma ORM untuk bertransaksi dengan basis data.
  6. Data dari database Neon PostgreSQL dikembalikan ke server.
  7. Antarmuka klien diperbarui secara reaktif tanpa me-reload browser secara penuh.

3.5. Keamanan Sistem (Arsitektur)

Dalam arsitektur ini, aspek keamanan diterapkan melalui fitur-fitur berikut:

  1. Proteksi CSRF Bawaan: Next.js Server Actions memvalidasi token permintaan secara otomatis.
  2. Pencegahan SQL Injection: Akses kueri terisolasi dalam kueri terparameterisasi Prisma ORM.
  3. Kontrol Hak Akses Berbasis Peran: Middleware memverifikasi peran (SUPER_ADMIN, ADMIN, STAFF).
  4. Enkripsi Kata Sandi: Password terenkripsi menggunakan algoritma hashing Bcrypt.
  5. Protokol HTTPS: Enkripsi jalur komunikasi end-to-end antara klien dan basis data cloud.
